APPLY THIS UPDATE (302) — LOCAL + LIVE
=====================================
This update fixes Render free wiping live publishes (note 302). Until now a
publish made on the live box lived on the nap-powered disk only: the next
sleep wiped it and the site fell back to the last deploy — content reverted
AND the publish stamp dropped, so visitors waited on maintenance as if a new
update had landed. From here on:

- Every save pushes itself to git seconds later (15s on Render, 2 min on the
  office computer), WITH a token when one is configured — so the publish is
  in the repo before the nap and the next boot clones it back.
- Render warns before sleep (SIGTERM): one last push attempt inside a 20s cap.
- Every content answer carries the backend's durability (token / disk /
  local / ephemeral — see window.__maintState().persist), and the Tools card
  warns while still ephemeral, with the free fix beside it.
- One-time free setup (5 minutes): GitHub → Settings → Developer settings →
  Personal access tokens → Fine-grained → this repo only → Contents read +
  write → Generate. Render dashboard → Environment → add GITHUB_TOKEN →
  Restart. No code changes after that — publishes just survive.
- Alternatives (no token): mount a Render disk at data/ and set PERSIST_OK=1,
  or publish from the office computer only (its words deploy by themselves).

LOCAL (your computer)
1. In the OLD folder: open #/admin → Tools → Back up now. Keep the file.
2. Extract THIS zip to a NEW folder (do not extract over the old one).
3. In the new folder: npm install
4. npm run dev → http://localhost:5173/  (admin: /admin)
5. BEFORE restoring: the site must show the maintenance notice ("We'll be
   right back", logo + message only, no links) — this update holds
   until blessed. That check is the point.
6. #/admin → Tools → Restore the backup file → Review and publish → Publish.
   Local lifts to 302 and the notice releases. Reload desktop + phone
   width to verify (a normal reload is enough — tabs now update
   themselves; no hard-reload needed).
7. Check: reload again with no new update — the site stays on the last
   published (no notice, published words intact). Console check:
   window.__maintState() shows publishedNotes 302.

LIVE (Render: twocchurch-site.onrender.com)
1. Add GITHUB_TOKEN in the Render dashboard (Environment) — see above.
   (Skip only if a disk is mounted at data/ with PERSIST_OK=1 set.)
2. Put this code where Render builds it (replace src/, scripts/, index.html,
   seed.json, vite.config.ts, package.json — keep data/ as-is), commit/push.
   Render: install npm install, build npm run build, start node scripts/serve.mjs.
3. Confirm https://twocchurch-site.onrender.com/version.json shows {"notes":302}.
4. The live site now waits on the maintenance notice until blessed. If it was
   wiped by sleep before, this is also the recovery: the notice is correct,
   the words come back with your backup. Even if a stamp from the local
   publish rode in with the deploy, the new build still holds until you
   publish here — a shipped stamp can never open it (fix 301b).
5. Open live /admin → Tools → Restore the backup file → Review and publish →
   Publish. This blesses 302 and lifts mobile + desktop together (no rebuild
   needed for this step). The push to git follows within seconds — check the
   Render logs for "auto-deploy: new words pushed".
6. Reload both modes (normal reload — tabs left open update themselves
   within a minute, no hard-reload needed). From here on a Render sleep must NOT revert words
   and must NOT bring the notice back — that is the fix being shipped. Verify
   by sleeping the service (or waiting for a nap) and reloading.

If desktop ever looks live while mobile waits: desktop is in ?preview=1
(gold Preview bar) — click Exit preview. Or clear that tab's preview flag.
