APPLY THIS UPDATE (301) — LOCAL + LIVE
=====================================
This zip locks maintenance so it can never vanish again. Rule from here on (note 301):

- A NEW, DIFFERENT update: fresh and new. The new code opens on its own
  words, visitors wait on the maintenance notice until the office restores
  a backup and Publishes — unchanged, now hardened:
  * a corrupt stamp (NaN, negative, unreadable) waits as unreviewed, never
    reads as published;
  * seed immunity is the browser's own memory BEFORE the bake lands;
  * a blank server answer can never bless or clear — the empty guard runs
    before the publish stamp is adopted;
  * a new history generation on the server is unreviewed (stamp reset) —
    visitors wait until the office publishes;
  * the notice itself keeps its update line + office doors (Preview the new
    site, Open the admin console), so the window never looks missing.
- NO new update: the copy REMAINS in the last published (note 300,
  unchanged). Only an explicit office delete (the Forget path) clears
  last-published. Sign-outs, password changes, restarts and rebuilds never do.
- Only an explicit office action lifts maintenance: publish, undo click,
  bless, offline flush (online or local). Heal never blesses. The feed, the
  baked seed, the server answer and the browser cache are witnessed evidence
  only — raise-only, never manufactured.
- Everything from 300 and before, unchanged.
- The pre-ship verifier has a new section H locking this rule — one FAIL
  blocks the ship. It passed for this zip.

4. npm run dev → http://localhost:5173/  (admin: /admin)

   right back") with "Update 301 installed · last published update ..." plus

6. #/admin → Tools → Restore the backup file → Review and publish → Publish.
   Local lifts to 301 and the notice releases. Hard-reload desktop + phone
