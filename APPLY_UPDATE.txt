APPLY THIS UPDATE (302) — LOCAL + LIVE
=====================================
This update fixes the vanishing maintenance notice for good. Symptom it kills:
after an update, visitors saw the live site instead of the notice, and only a
hard refresh (Ctrl+Shift+R) brought the notice back. Rule from here on
(notes 301 + 302):

- A NEW, DIFFERENT update: fresh and new. The new code opens on its own
  words, visitors wait on the maintenance notice until the office restores
  a backup and Publishes — unchanged from 301, plus the notice can no longer
  be skipped by cached files:
  * a normal reload is enough — no hard refresh, ever. The entry page
    (index.html), version.json, seed.json, server.json and feed.json are
    never cached anywhere (static hosts get _headers + .htaccess, the office
    server sends no-store), the version check is cache-busted, stale reloads
    retry instead of trapping on the old bundle, the app holds the boot
    splash until the version check settles, and an inline gate in index.html
    paints the notice before React even boots.
  * everything 301 locked still holds: a corrupt stamp waits, seed immunity
    is pre-bake memory, blank answers never bless, a new history generation
    is unreviewed, and the notice stays logo + message only.
- NO new update: the copy REMAINS on the last published (note 300,
  unchanged). Only an explicit office delete (the Forget path) clears
  last-published. Sign-outs, password changes, restarts and rebuilds never do.
- Only an explicit office action lifts maintenance: publish, undo click,
  bless, offline flush (online or local). Heal never blesses. The feed, the
  baked seed, the server answer and the browser cache are witnessed evidence
  only — raise-only, never manufactured.
- Everything from 301 and before, unchanged.
- The pre-ship verifier has a new section I locking this fix — one FAIL
  blocks the ship. It passed for this zip.

2. Extract THIS zip to a NEW folder (do not extract over the old one).
3. In the new folder: npm install
4. npm run dev → http://localhost:5173/  (admin: /admin)
5. BEFORE restoring: the site must show the maintenance notice ("We'll be
   right back", logo + message only, no links) — this update holds
   until blessed. That check is the point. A plain reload must show it;
   no hard refresh needed.
6. #/admin → Tools → Restore the backup file → Review and publish → Publish.
   Local lifts to 302 and the notice releases. Reload desktop + phone
   width to verify (plain reloads).
7. Check: reload again with no new update — the site stays on the last
   published (no notice, published words intact). Console check:
   window.__maintState() shows publishedNotes 302.
