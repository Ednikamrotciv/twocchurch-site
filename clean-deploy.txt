Clean new deploys live here: while this file sits beside package.json,
every deploy ships no words — fresh, new and clean (welcome-home slide
only, unsaved changes empty) until the office clicks Recover and Publish.

It arrives with the update and the first Publish consumes it by itself
(the push commit deletes it), so the next rebuild carries words and
sleep-wakes serve them. Each new update re-ships it, so every new code
deploy opens clean again. Nothing is ever deleted anywhere: backups, the
office disk and the root seed.json keep everything.

While this file is present the server itself also opens clean: the boot
guard parks any previous store aside under a timestamped data-backups/
name (restorable with `npm run restore`), the backend starts with no
words, and the live-follow loop holds — so old slides cannot re-serve
from disk, backups or live until Recover + Publish.
