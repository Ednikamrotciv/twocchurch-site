WHAT WAS WRONG (why every redeploy broke the livestream)
--------------------------------------------------------
1. This zip used to contain a file called clean-deploy.txt. While that file
   sits beside package.json, EVERY build ships EMPTY words (no content) and
   every deploy opens on the maintenance "We'll be right back" screen until
   the office clicks Recover + Publish. That looked like a "page error".
   --> FIXED IN THIS ZIP: clean-deploy.txt has been REMOVED, so builds now
       carry your words again. Do NOT put that file back unless you want a
       fresh-clean opening (Recover + Publish, then remove it and rebuild).
2. The live backend (Render) was on update 441 while this bundle is 442, or vice versa.
   Mixed versions ignore each other's live reports, so visitors fall back to
   slow direct YouTube reads: endless spinner, then the grey circular-arrow
   error that never heals.
   --> FIXED BY PROCEDURE: redeploy BOTH sides from THIS zip so both sides
       are 442. Never run the frontend and the backend on different updates.
3. If the red "Watch on YouTube" button works but the site player shows the
   grey arrow, the office Play switch is ON while no broadcast is actually
   live (or embedding is disabled in YouTube Studio). The arrow's repair
   re-asks and gets the same answer, so it never heals by itself.

IF YOU SEE "SOMETHING WENT WRONG ON OUR SIDE" (PAGE ERROR CARD)
---------------------------------------------------------------
That card means a page chunk failed to load after the deploy — almost always
a stale/mixed deploy: the browser kept the OLD entry page, which names
script chunks the new deploy pruned (or the upload is incomplete, or a CDN
is mixing old + new files). Home still works because it loads eagerly;
Watch live / Admin load their chunks on demand, so they are the ones that
trip it. This build self-heals it: a failed chunk reloads the page once to
fetch fresh chunks (one per chunk per tab); only a repeat failure shows the
card. Do this:
1. Press the card's "Reload the page" button once. If the page now works,
   it was stale chunks — done, nothing else is broken.
2. If it keeps coming back: the deploy itself is mixed. Re-upload the FULL
   contents of dist/ (no partial uploads — FTP/cPanel uploads are NOT
   atomic, so upload everything before testing), purge any CDN/host cache
   (Cloudflare etc.), hard-refresh (Ctrl+Shift+R), then Publish once.
3. Check integrity: /version.json (notes + code + deployId) must match the
   wom-notes / wom-code / wom-deploy metas in the served index.html
   (view-source). Mismatch = mixed deploy = repeat step 2.
4. If the card persists on one device/host only, open its new "Error details"
   (for the office) line, screenshot it, and send it to the developer: a
   "Failed to fetch dynamically imported module" message means that host's
   dist/ upload is incomplete (re-upload fully + purge cache); any other
   message names the exact render throw to fix.
